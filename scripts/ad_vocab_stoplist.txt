# Stop-list for the AD VOCABULARY check in mechanical_checks.py.
# source-hash: 02abc732118f scripts/ad_vocab_stoplist.txt
#
# The check prints phrases that appear in the job ad AND in the outgoing documents but NOT in
# your facts file - the pattern that predicted 4 of 10 over-claims in one pass on the corpus
# this toolkit comes from ("data fusion", "reconciliation", "reporting documentation",
# "translating business requirements into dashboards"). Ordinary English dominates a naive
# implementation, so this file is the noise floor.
#
# TWO KINDS OF ENTRY, distinguished by whether the line has a space in it:
#
#   single word   a function word. Used two ways: a phrase made only of these is dropped, and
#                 a phrase that STARTS or ENDS with one is dropped ("of the reporting" is not
#                 a phrase anyone adopted, it is a window that happened to align).
#   multi-word    a phrase suppressed exactly. These are judgement calls - vocabulary every
#                 application shares, where adoption carries no claim - so
#                 test_mechanical_checks.py probes each one structurally. Single words are
#                 covered structurally too; probing 90 function words individually would be
#                 ceremony, not coverage.
#
# Add entries for your own market's boilerplate (visa and work-rights phrasing, salary and
# notice-period questions) - a cover letter that appends screening answers shares that
# vocabulary with the ad by construction. Never add a phrase that could carry a claim.
#
# Lowercase, one per line. Blank lines and #-comments ignored.
